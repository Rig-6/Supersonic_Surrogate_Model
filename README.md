# Supersonic Drag Surrogate

## Mission Statement

The goal of this project is to create an end to end supersonic drag data generation pipeline for the training of a machine learning model meant to take the place of costly CFD analysis in general shape optimization surveys. 

## Updated Results

Twenty geometries have been sampled, meshed, and solved end-to end purely with scripts. The results demonstrate drag falling with reduced slenderness, correlating with basic supersonic wave-drag theory. 

## The Process: Step by Step

**1. Parameterized Geometry Generation**

[`vsp_geometry/generate_vsp_geometry_LHS.py`]

A Latin Hypercube (`scipy.stats.qmc` , seed: 42) samples 20 (sample size is customizable) points over fineness ratio and diameter. Each sample creates an OpenVSP 'POD' axisymmetric shape, and then exports it as a watertight STEP file. Every file gets a SHA-1 run ID, derived from unrounded parameters so files with the same rounded parameters aren't overwritten and can be differentiated and tracked throughout the pipeline.

**2. Farfield Domain Generation**

[`vsp_geometry/farfield_geometry_optimizer.py`]

Gmsh imports every POD, builds a cylindrical volume around it (2 body-lengths upstream, 5 downstream, and 10 diameters across), and boolean subtracts the cylinder to leave a fluid domain. The generated fluid domain is exported as a STEP file.

**3. Meshing and Solving**

[`vsp_geometry/integrated_meshing_simulation_workflow.py`]

The meshing and solving is driven by the PyFluent API for Ansys Fluent. The process uses the Fluent Meshing watertight workflow.

The key settings include
- Cone wall face zone identified by surface area.
- Local sizing is applied to the cone wall, generating a finer mesh in more important areas and a coarser one in less important areas. This allows for efficient cell meshing and solving time while retaining data quality.
- Poly-hexcore volume fill is used with the edge length derived from the measured domain volume.
- Density-based implicit solver, k-omega SST, AUSM flux, ideal-gas air with three-coefficient Sutherland viscosity.
- Reference area for drag calculation is measured from the mesh.
- Iteration is conducted in blocks of 25 iterations where drag coefficient is calculated every block. 
- The solving run is considered "converged" when the latest four drag coefficient values agree within 0.1% of their values.

## Getting started

### Requirements

| | |
|---|---|
| **Python 3.13** | Required — OpenVSP's bundled bindings are built against it |
| **OpenVSP** | Free and open source, [openvsp.org](https://openvsp.org) |
| **Ansys Fluent 2025 R2** | **Commercial license required** — stages 3 and 4 cannot run without it |

Stages 1 and 2 run on free software alone. If you do not have a Fluent license you can still generate geometry and farfield domains, and the published `simulated.csv` gives you the labelled data without re-solving.

### Install

```bash
git clone https://github.com/Rig-6/NoseConeProML.git
cd NoseConeProML
python -m venv .venv
.venv\Scripts\activate          # Windows;  source .venv/bin/activate on Linux
pip install -r requirements.txt
```

OpenVSP's Python bindings are not on PyPI. Install OpenVSP to `C:\OpenVSP`, or set `OPENVSP_PYTHON_PATH` to the folder containing the `openvsp`, `degen_geom`, `utilities`, and `openvsp_config` packages.

The most reliable setup is the conda environment OpenVSP ships:

```bash
conda env create -f C:\OpenVSP\python\environment.yml
conda activate vsppytools
python test_vsp.py        # should print a POD geometry ID
```

### Run

```bash
python vsp_geometry/generate_vsp_geometry_LHS.py                 # minutes
python vsp_geometry/farfield_geometry_optimizer.py               # minutes
python vsp_geometry/integrated_meshing_simulation_workflow.py    # hours per case
```

Stages 2 and 3 skip cases whose output already exists, so an interrupted sweep can be restarted with the same command.

## Roadmap

While the progress made so far has been incredible and an amazing learning experience, much needs to be done for this project to be considered a viable proof of concept.

- **Refine Data Generation:** An effective model relies largely on the data it is trained upon. Planned: Greatly raise sample size from 20, implement mach sweep from subsonic to transonic to supersonic.

- **Drag Baseline:** Before trusting a machine learning model, it needs to be compared to some sort of a baseline. Planned: Build a basic regression model using a fit regression curve.

- **Machine Learning Surrogate:** One of the final phases to this project, building the machine learning surrogate is one of the most important parts of this experiment. Planned: Create and train a basic regression model like XGBoost before creating and training a custom pytorch model.

- **Extrapolation Problem Solving:** Once a successful machine learning surrogate model has been created, it can be used to evaluate optimal design parameters given a Mach number. Planned: Use saved model information to obtain optimal parameters for minimized drag coefficient given a Mach number.

## Known limitations

Stated plainly, because they affect how the numbers should be read.

- **The results table is incomplete.** All 20 cases have solved case/data files on disk, but `simulated.csv` is currently rewritten from scratch on each run while already-solved cases are skipped — so rows from earlier runs were lost. Fixed rows are being re-exported from the saved `.dat.h5` files.
- **`Fineness_Ratio` in `parameter_combinations.csv` stores L/R, not the conventional L/D.** Figures in this README use L/D. The column will be renamed.
- **Cell counts run 0.9–2.1 M against a 750 k target.** The hex sizing is derived from domain volume, which does not fully control the surface-driven refinement. Mesh independence has not been formally demonstrated.
- **Base drag is included.** The POD is a closed body, so reported drag coefficient covers forebody wave drag, skin friction, and base pressure together. It is not directly comparable to published sharp-cone wave-drag coefficients.
- **Single Mach number.** Every result here is at M = 2.0.
